Cut 1

Offload: keep big results in files, give the model a stub

def offload(name, args, result):
    if len(result) <= LIMIT:
        return None                 # keep it
    path = RESULTS / f"{name}_{n}.json"
    path.write_text(result)
    return json.dumps({
        "offloaded": path.name,
        "chars": len(result),
        "preview": result[:120]})
# plus a tool: read_result(file, start, length)
5,414 → 4,150

Nothing is lost

The full result is one tool call away.

Offloading moves information; it does not delete it. The risk is the opposite one: a model that never reads the file and answers from the preview. The trace shows whether read_result was called. Coding agents do the same with long command output.

A bug we hit

The second compaction dropped the first one's notes. Carry them forward.

The course's own reference solution had this bug until the scripted run caught it: compaction runs again on a history that already holds notes, and a naive version throws them away. Two safety rules: never split a tool call from its result, never drop the task. A model can write the notes instead of code; it costs a call and may drop an ID.

Retrieval for agents

For an agent, search is a tool it decides to call

Classic retrieval

Search once, paste the passages into the prompt, answer.

Agentic retrieval

The agent chooses the query, the tool, whether to read a whole document, and when it has enough.

So the tool's contract matters

What it is good at, in its description. What it returns: IDs to cite, the status of each circular, short passages.

Bosla has search_circulars and get_circular since Day 1. This session asks how good the search is, and which of two searches the agent picks when it has both. The answer is in the trace, not in a guess.

Keyword search done properly

BM25, Arabic normalisation, and a penalty for superseded

def normalise(text):
    text = re.sub(r"[ً-ْـ]", "", text)
    text = re.sub("[أإآ]", "ا", text)
    text = text.replace("ة", "ه").replace("ى", "ي")
    return text.lower()
# BM25: rare words count more, repeats less
# superseded chunks: score x 0.5

Normalise

One Arabic letter has several written forms. Unify them before matching.

Rank by status

The protection against TC-02 lives in the ranking, where code enforces it.

BM25 is the standard keyword scorer: term rarity times a saturating term frequency, normalised by length. The status penalty is a design choice of this course; another valid one is to drop superseded chunks from the index and keep a pointer. Ask which is safer for a historical question.

A parallel case, not Lab 2.2: a pilotage handbook of numbered sections (PH-xx), synthetic. Retrieval scores like the ones on the last slides say nothing about what the model does with a long packed context. Models tend to use the start and the end of a long input better than the middle (Liu et al.). The packer here throws away the ranking by sorting passages into handbook order. Ask: what experiment would prove that position, and not the content, is the cause? Sources: Liu et al., Lost in the Middle.

The diagnosis

Same content, same question: only the position changed, and accuracy fell in the middle. The cause is position.

The fix

Keep the ranking when packing: best first, fewer passages. Then run the ablation again.

Synthetic numbers, written with a fixed seed by labs/_tools/make_diagnostics.py (data/reference/position_ablation.jsonl); they illustrate the method, they are not a model run. The ablation changes one variable: every run has the same 20 sections, and only the right one moves. A U shape (high at the ends, low in the middle) points at position; a flat low line would point at the passage itself or the question. Five trials per cell, because one run per position is noise. A bigger context window is not the fix: the window was never full. Sources: Liu et al., Lost in the Middle.

03
What goes where

Context file, skills, memory: three stores, three lifetimes

Context file

Every session needs it: the port, how to work, what never to do. Short. Always loaded.

Skill

Some tasks need it: how to quote a tariff, how to change a booking. A one-line index entry; the body on demand.

Memory

Learned in one session, needed in another: "Faisal prefers Arabic". Written by the agent, capped.

Coding agents use the same three: a file such as AGENTS.md at the root of a repository, skills as folders with a SKILL.md, and memory files. The names differ by product; the lifetimes are what matter. Ask: where would the rule "TC-02 is superseded" go? In the context file, because every session needs it.

data/bosla/AGENTS.md

A context file is short on purpose

## How to work
- Look up before you answer.
- For any price, load the skill tariff-quote.
- For any amendment or cancellation,
  load the skill booking-change.
- TC-02 is superseded by TC-07.

## Never
- Reveal another agent's bookings (TC-05).
- Write without an explicit request.

Pointers, not procedures

It says when to load a skill; the skill says how.

Paid on every call

Every line is in every request, for the whole session.

A skill is a folder

Front matter for the index, a body for the procedure

---
name: tariff-quote

The description is a trigger

It is all the model sees until it loads the skill. Write when to use it, not what it is.

The tariff-quote skill and its reference.md of worked examples are in the repository. The worked examples are real outputs of compute_dues: Sahil Tide, 36,000 GT, 3 days with dangerous goods, is SAR 12,960.

04
Model Context Protocol

A protocol lets any host discover tools it was not written with

Without it

Every host imports every tool: Bosla's code, an IDE's plugin and a desktop app each wrap the circulars their own way.

With it

One server over the circulars. Each host connects, asks what is there, and calls it.

A server offersExample
toolssearch_circulars, get_circular
resourcescirculars://index, circular://TC-07
instructions"A superseded circular no longer applies."

MCP is JSON-RPC between a host's client and a server, over stdio for a local process or HTTP for a remote one. The protocol is revised regularly: check the current revision at modelcontextprotocol.io before the cohort and update the SDK pin in labs/pyproject.toml if needed.

Lab 2.4 · step 2

A server is decorated functions

server = MCPServer("marsa-circulars", instructions="...")

@server.tool()
def get_circular(circular_id: str) -> dict:
    """Read one whole circular by ID (TC-01 to TC-08)."""
    try:
        return p.get_circular(circular_id)
    except port.ToolError as e:
        raise ToolError(str(e)) from e     # the model reads it

@server.resource("circular://{circular_id}")
def circular(circular_id: str) -> str: ...

Type hints become the input schema, the docstring becomes the description: the same contract as Day 1's typed tools. Converting the case study's ToolError into MCP's ToolError is what makes an unknown circular an error result the model can act on, rather than a hidden server crash.

A concept for Day 4

Agent-to-agent: delegate a task, not a function call

MCPAgent-to-agent
Other sidea server of tools and documentsanother agent with its own model and tools
You senda tool call with argumentsa task in words

The A2A protocol describes an agent with a card (what it can do) and a task lifecycle. Day 4 splits research and drafting between two agents and asks when that pays.

The entry lists agent-to-agent delegation as a concept only: one slide here, the comparison on Day 4. Keep it to the distinction in the table: a tool call is precise and immediate; a delegated task is open-ended and has its own costs and failures.

Day 2 recap

Context is a budget you spend on purpose

  • Measure tokens per turn; tool results grow fastest.
  • Offload moves information; compaction can lose it. Judge both on success.
  • Retrieval: score the top hit; protect against superseded text in the ranking.
  • Context file always, skills on demand, memory capped.
  • MCP: tools and resources discovered at run time, tested through the protocol.
